Interfaces that live

Some screens are never finished: runs, queues, agents, a balance. Since 1.2, kubik draws them in time. An axis with a line for now, history on its left, only what is scheduled on its right, and silence drawn with its age.

One brief, built twice

The brief: a live console for an agent platform, where the operator watches runs through the day and opens one to see why it failed. On the left, what kubik 1.0 built from it. On the right, what kubik 1.2 built. One build each, from one throw of the dice, shown as it came out, on sample data. Press either to look closer.

Four more, made with 1.2

Other screens people operate, each in a character of its own. Each is one build from one throw of the dice, shown as it came out. Press one to open it.

We tested it blind. Five interfaces, each built three ways: with kubik 1.2, with kubik 1.0 and with no skill. A critic who did not know which build was which scored every one out of 25. Kubik 1.2 came first on all five, with 114 points of a possible 125. Kubik 1.0 took 106 and the builds with no skill 87. Each cell is a single build.

Inside your system

Give kubik a finished design system and a whole product screen, and it throws one new component for a place on that screen. Throw the engineering die: the face that lands unfolds into a live component inside the marked region, built only from the system's own tokens. Each throw draws a different invented system and product too, so the screen around the component changes. From any input (CSS variables, a Tailwind config, JSON tokens, a DESIGN.md, a screenshot) kubik first writes one map of it, and builds only from the map.

How the dice get thrown

Five steps, the same for a page, a report, a deck, a page of figures or a design system.

  1. You say what you want to see

    A mood, a colour, a reference, what you are tired of. Whatever you leave unsaid is read from the occasion: who reads the piece, where, and what they do with it.

  2. Your words and the occasion tilt the dice

    A thing you name is settled. A direction gets more weight. Then the dice are thrown for what is left, with a real random source, so the work does not start from the likeliest answer.

  3. Three concepts, one signed

    Each concept fits in a line. The one worth signing is chosen, and one moment is named: the thing a visitor would stop on.

  4. Everything stands in one frame

    True content, text that can be read, every width, the keyboard, controls that answer, motion that can be stopped. Repair the defect, keep the effect.

  5. A real browser looks first

    The piece is opened at desktop and phone width, in dark mode and with reduced motion, walked with the Tab key and rendered once without script. A closing note says what was done.
